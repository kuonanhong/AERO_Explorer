AERO Explorer v3：GitHub 上傳、實景設定與大量流量部署教程

版本：2026-10-07。對象：第一次將 AERO 網頁遊戲發表到 GitHub Pages，或準備規劃大量訪客的網站管理者。本指南使用繁體中文，命令以本套件的 Node.js 建置與 dist 原始碼／發布目錄為基礎。

1. 先了解這次交付及「10 萬人」的含義

這個版本把載具物理、操作、繪圖與拍照放在玩家自己的瀏覽器計算。玩家甲按鍵不會造成主機為玩家乙額外計算一架飛行器；網站主機主要處理 HTML、JavaScript、圖片等下載。因此，只要靜態資源供應容量足夠，許多人可以同時到同一網址，各自在自己的裝置玩。

目前沒有實作多人共用同一世界、互看載具、即時碰撞、聊天或排行榜伺服器。「10 萬人開啟同一網站」與「10 萬人在同一世界同步」是不同的系統。若將來需要共用世界，必須另建房間、權威伺服器、狀態同步與負載規劃；不能只改 HTML 就取得這項能力。

本版本已提供的降負擔設計包括：

  • 啟動前能力偵測與渲染探測，自動選完整、均衡、輕量模式。
  • 輕量模式使用 Canvas，避免裝置無法建立 3D WebGL 時完全無法操作。
  • 3D 模組延後下載，水下礁石素材只在需要時載入。
  • 22 語系介面、166 個介面字串，以及 13 處景點的多語介紹。
  • 每位玩家獨立模擬；沒有每幀傳送載具位置給網站主機。
  • Service Worker 只快取白名單中的自有資產，不預取或快取 Google 圖資。
  • Google 實景、Street View、附近景點及天氣是選用功能，失敗時回到本機可玩的場景。

這些設計降低負擔，但目前沒有完成 10 萬名真人、10 萬臺裝置或正式 CDN 的同時連線驗證。不能將本地測試或容量推算寫成「已保證 10 萬人永不當機」；玩家的舊瀏覽器、電池、記憶體、背景程式、網路與外部 API 都會影響結果。

2. 套件中哪些檔案應上傳

請先解壓完整套件，再將專案目錄上傳 GitHub。index.html、樣式、指令碼與素材必須成為實際網站檔案；只把一個 ZIP 放在 repository，GitHub Pages 不會自動將它解壓成遊戲。

內容 用途 是否放進發布的 dist
HTML、CSS、瀏覽器 JavaScript 遊戲執行與介面 是
自有圖片、WebP、GLB、音效 網頁場景素材 是，依遊戲使用情況
Service Worker、manifest 安裝／離線與自有資產快取 是
package.json、package-lock.json 還原建置環境 放原始碼 repository
原始碼、建置指令碼、測試 修改及驗證 放原始碼 repository
本指南與技術說明 管理者閱讀 可放原始碼；不必讓遊戲啟動下載
node_modules npm 安裝後產生 不放
Windows EXE、Phoenix 安裝器、原始大型素材 ZIP 參考／獨立軟體 不放遊戲發布目錄
大型錄製影片、完整備份 ZIP 下載附件 建議用 Release 或適當物件儲存
私有 API key、登入 token、密碼 帳號／後端認證 不放公開原始碼與網站

本遊戲不需要 Phoenix Windows 安裝器才能在 Mac、Windows、Linux、手機或平板開啟。不要為了「完整」把幾百 MB 的 EXE 連同網站一起部署，也不要未確認素材權利就重新發布第三方模型、貼圖或安裝程式。

此專案的原始碼也位於 dist，所以必須完整提交 dist/，不能把它加入 .gitignore。 例如 game.js、physics.js、scene.js、device.js、geo.js 及 assets/i18n.json 都是建置所需來源。Actions 在這些檔案上重新產生 bundle／語系入口，再發布整個 dist；它不是從空目錄還原出遊戲。若選擇純手動部署，也需發布整個 dist 的內容，不能漏掉延後載入的模組或素材。

3. 安裝 Git、Node.js 與 GitHub 登入工具

3.1 Mac：終端機操作

在「應用程式 → 工具程式 → 終端機」開啟 Terminal，先確認：

git --version
node --version
npm --version

若已有工具，就不必重新安裝。本次建置與核心契約測試使用 Node v24.19.0；下方 Actions 範例選用 Node 24 系列。安裝後重新開啟 Terminal。可以從 Node.js 官方下載頁 選擇 macOS 安裝程式。Git 可以使用 Apple Command Line Tools，或 Git 官方 macOS 安裝選項。

Node 24 官方 macOS 預先編譯版本最低要求 macOS 13.5。如果你的 Mac 仍是較舊系統而無法安裝這個 Node，仍可提交原始碼，交由 GitHub Actions 的 Ubuntu／Node 24 建置，不必在本機強裝不相容版本。玩家開啟發布後的遊戲本身不需要 Node.js。來源：Node.js 官方 v22 到 v24 遷移說明。

如果你已安裝 Homebrew，也可安裝 Git 與 GitHub CLI：

brew install git gh

這條命令假設 brew 已存在，不要把「沒有 Homebrew」誤當遊戲故障。你也可以全程使用 GitHub Desktop，最後在 GitHub 網站設定 Pages。

3.2 Windows：PowerShell 操作

開啟 Windows Terminal 或 PowerShell，先確認與 Mac 相同的版本命令。如果系統有 WinGet，可用以下方式安裝 Git 及 GitHub CLI；Node.js 24 請從官方下載頁選擇該系列的 Windows 安裝程式：

winget install --id Git.Git -e
winget install --id GitHub.cli -e

安裝完成後關閉、重開 PowerShell，讓 PATH 更新，再執行：

git --version
gh --version
node --version
npm --version

Windows 命令若顯示找不到 git、gh 或 node，先處理安裝/PATH，不需要修改遊戲。若 PowerShell 的原則阻擋 npm.ps1，可以用 npm.cmd 執行同樣的 npm 命令，或使用 Git Bash；不要為了一個命令而關閉整臺電腦的安全設定。

3.3 登入 GitHub

GitHub 網站建立帳號並登入後，可透過 GitHub CLI 的瀏覽器流程連結帳號：

gh auth login
gh auth status

選擇 GitHub.com、HTTPS，再選瀏覽器登入。GitHub 不再接受帳號密碼當作 HTTPS Git password；若沒有 CLI，可使用 GitHub Desktop 或自行設定 SSH。不要把 personal access token 寫到命令範例、JavaScript、網址、README 或截圖中。

只需設定本專案作者資訊即可：

git config user.name "Nan-Hong Kuo"
git config user.email "YOUR_GITHUB_EMAIL"

這兩條命令要在 git init 或 clone 後的專案內執行。請將 email 換成自己的 GitHub 公開信箱或 GitHub 提供的 no-reply 信箱；提交記錄可能公開。

4. 第一次上傳到新的 GitHub repository

4.1 建立空的遠端 repository

在 GitHub 右上角「＋ → New repository」建立，例如 aero-explorer。個人免費帳號的 Pages 一般以 public repository 發布。首次操作先不要勾選 Add a README、license、.gitignore，讓遠端保持空白，避免與本地已有檔案衝突。

假設帳號是 YOUR_USERNAME，repository 是 aero-explorer：

  • 原始碼網址：https://github.com/YOUR_USERNAME/aero-explorer
  • 預期 Pages 網址：https://YOUR_USERNAME.github.io/aero-explorer/

這是專案網站。如果 repository 名稱正好是 YOUR_USERNAME.github.io，網站通常位於 https://YOUR_USERNAME.github.io/ 根路徑，設定方式見第 6 章。

4.2 切換到解壓後的專案

Mac 範例（以實際資料夾名稱取代）：

cd "$HOME/Downloads/AERO_Explorer_v3"

Windows PowerShell 範例：

Set-Location "$env:USERPROFILE\Downloads\AERO_Explorer_v3"

用檔案總管確認這一層含有 package.json，不是 ZIP 上層目錄，也不是只有 dist/index.html 的子目錄。

4.3 本機還原依賴與建置

npm ci
npm run build
npm test

npm ci 依 package-lock.json 安裝，適合重現本套件版本。若因網路造成下載失敗，修復網路後重試；不要刪掉 lock 檔來繞過問題。建置成功後確認 dist/index.html 及所有資產存在。

進行發布建置時，應明確指定最終網站網址。Mac／Git Bash：

AERO_ORIGIN="https://YOUR_USERNAME.github.io/aero-explorer" npm run build

Windows PowerShell：

$env:AERO_ORIGIN = "https://YOUR_USERNAME.github.io/aero-explorer"
npm run build
Remove-Item Env:AERO_ORIGIN

AERO_ORIGIN 是此專案的完整發布基底網址，包含 repository 子路徑，即使名稱叫 ORIGIN 也不能在專案網站只填主機名。範例不要加最後的 /。它用來生成 canonical、語系替代連結及 sitemap 等發布資訊；實際 API key 的 website restriction 則通常只限主機來源，兩者不同。

4.4 初始化、提交、上傳

以下命令在 Mac、Git Bash、PowerShell 都可逐行執行：

git init -b main
git config user.name "Nan-Hong Kuo"
git config user.email "YOUR_GITHUB_EMAIL"
git status
git add .
git status
git commit -m "Publish AERO Explorer v3"
git remote add origin https://github.com/YOUR_USERNAME/aero-explorer.git
git remote -v
git push -u origin main

先看 git status，確認沒有 node_modules、大型 ZIP／EXE、私有 token。git add 把檔案放入待提交區，commit 建立本地版本，git push 才是把版本送上 GitHub。你原先說的「git pull 到 GitHub」，對應的是這裡的 push；pull 是從 GitHub 拉回本機。

若已使用 GitHub CLI，也可把「建立遠端＋設定 remote＋push」交給 CLI；這與上一段二擇一，不要兩種都執行：

gh repo create aero-explorer --public --source=. --remote=origin --push

CLI 這條命令假設 repository 尚未存在、本地已有 commit、也未設定同名 origin。已在網頁建 repo 就用前面 git remote add 流程。

5. 自動發布：GitHub Actions

5.1 準備 workflow

本指南附 pages.yml 範例，應放進專案：

.github/workflows/pages.yml

把其中 AERO_ORIGIN 的 YOUR_USERNAME 與 aero-explorer 改為你的帳號、repository。此 workflow 使用 Node 24、npm ci、npm run build 及 npm test，只將 dist 發布到 Pages；原始碼中的 dist 必須已提交。

name: Publish AERO Explorer

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  publish:
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    env:
      AERO_ORIGIN: https://YOUR_USERNAME.github.io/aero-explorer
    steps:
      - name: Check out source
        uses: actions/checkout@v6
      - name: Set up Node
        uses: actions/setup-node@v6
        with:
          node-version: '24'
          cache: npm
      - name: Restore dependencies
        run: npm ci
      - name: Build site
        run: npm run build
      - name: Test core contracts
        run: npm test
      - name: Configure Pages
        uses: actions/configure-pages@v5
      - name: Upload dist
        uses: actions/upload-pages-artifact@v4
        with:
          path: dist
      - name: Deploy site
        id: deployment
        uses: actions/deploy-pages@v4

主要 action 版本是相容性選擇，將來升級時請對照官方發布說明，不要不經測試自動替換成不同 major。需要更嚴格供應鏈管理時，可以將 action tag 換成查證過的完整 commit SHA。

5.2 GitHub 網頁設定

開啟 repository，依序選：

  1. Settings → Pages。
  2. Build and deployment 下的 Source 選 GitHub Actions。
  3. 回到 Actions 分頁，找到 Publish AERO Explorer。
  4. 若 workflow 已提交但沒有跑，選 Run workflow；或推送新的 commit。
  5. 點開執行結果，確認每一步成功；Deploy site 會顯示發布網址。

第一次發布需要一點時間。成功的 workflow 不等於一定用了你預期的網址；請開啟實際的 Pages URL，再測鍵盤、手機操作、語系切換、3D、下水、拍照及離線回訪。

加入／修改 workflow 後上傳：

git add .github/workflows/pages.yml
git commit -m "Configure GitHub Pages deployment"
git push

Actions 檔案不是放在 dist/.github；必須放 repository 根目錄的 .github/workflows。若套件已附 workflow，就修改既有檔，不要建立兩個相同用途流程。

6. 子路徑、自訂網域與搜尋網址

6.1 三種網址的設定

發布方式 網站網址 AERO_ORIGIN
專案 Pages https://USER.github.io/aero-explorer/ https://USER.github.io/aero-explorer
個人根網站 https://USER.github.io/ https://USER.github.io
自訂網域 https://play.example.org/ https://play.example.org

不要把範例 USER、example.org 原樣發布；那會讓 canonical 和 sitemap 指向別人或不存在的網站。

在 /aero-explorer/ 之下，若程式誤用 /assets/app.js，瀏覽器會取根網站的資產。正確載入應依本套件的相對路徑／base 設計：./assets/... 或與 document.baseURI 相符的地址。不要在所有檔案前人工加一次 repo 名，因為可能重複成 /aero-explorer/aero-explorer/。

離線 Service Worker 的註冊與 scope 也應留在專案發布路徑內，不攔截整個 USER.github.io 的其他遊戲。HTML 必須包含其對應版本的全部資產，不能新 HTML 搭配舊 bundle。

6.2 變更自訂網域

先在 GitHub Settings → Pages 設 Custom domain，照官方指示設定 DNS；不能只放一個 CNAME 檔就認為完成。等 HTTPS 可用後，修改 workflow 的 AERO_ORIGIN，重新建置發布，並同步修改 Google browser key 的 website restrictions。

正式換網址後確認：

  • 頁面 canonical 指向新網址。
  • 22 個語系連結沒有指向舊網站或錯誤子路徑。
  • sitemap 使用正確網址；Google Search Console 可由站主提交。
  • 地圖 API key 的允許來源已含新網域。
  • 舊書籤、舊快取、安裝的 PWA 有明確更新方式。

SEO 與 AI 搜尋可讀的標題、說明、多語介紹及 sitemap 有助發現，但不保證排名、收錄時間或訪客數；網站須真的公開、HTTPS 可讀且沒有登入封鎖。

7. 已有 repository：更新與安全同步

7.1 尚未下載遠端版本

不要在同一資料夾重複 git init。先 clone：

git clone https://github.com/YOUR_USERNAME/aero-explorer.git
cd aero-explorer
npm ci

將新套件的原始碼、素材及說明比對後複製進該專案；不要複製另一套件的 .git。保留自己的 deployment URL、owner config 及需要保留的修改。

7.2 每次修改前先取得遠端更新

git status
git pull --rebase origin main

這是「GitHub → 本機」的 pull。--rebase 將你尚未分享的本地提交重放到最新遠端版本，保持線性記錄。先讓工作目錄乾淨；如果有未提交修改，先提交或暫存，不要直接覆蓋檔案。

暫存工作目錄的常見流程：

git stash push -u -m "Work before syncing"
git pull --rebase origin main
git stash pop

stash pop 仍可能衝突，-u 包含未追蹤檔但不包含被忽略的 node_modules。暫存不是永久備份；重要工作仍應提交或另存。

7.3 本地修改完成後再上傳

npm ci
npm run build
npm test
git diff --stat
git status
git add .
git commit -m "Improve AERO scenes and controls"
git push origin main

每次推送後檢查 Actions。網站上的使用者可能仍有上一版快取；不要要求使用者反覆清除所有瀏覽器資料。正常版本更新應由帶版本資產、Service Worker lifecycle 及頁面更新提示完成；排錯時才用該站點的清除／重新載入。

7.4 發生衝突

git status

開啟列出的檔案，找到衝突區，選擇正確內容並刪除 <<<<<<<、=======、>>>>>>> 標記，再：

git add PATH_TO_RESOLVED_FILE
git rebase --continue

如果不能確定，先停止這次整合：

git rebase --abort

這會返回 rebase 前的狀態。不要用 git push --force 當一般排錯方式，也不要把 git reset --hard 放成第一個建議；它可能丟掉自己的修改。

8. 檔案很大：Git、LFS、Release 如何選

8.1 目前官方大小限制

GitHub 普通 Git 檔案超過 50 MiB 會警告，超過 100 MiB 會拒收；在網頁直接上傳單檔最大 25 MiB。GitHub 建議 repository 維持小體積。Pages 發布網站最大 1 GB，不是「repository 有成功上傳」就能發布任意大小網站。[S1][S2]

Git LFS 可以把大型檔案內容放到獨立儲存，再於 Git 保留 pointer；但官方明確說 Git LFS 不能用於 GitHub Pages 網站。不要把遊戲需要的 GLB 放 LFS，然後以為瀏覽器會下載真正模型，因為可能得到 pointer 文字。[S3]

需求 建議
小型 HTML、JS、CSS、語系 普通 Git
遊戲所需已壓縮圖片、GLB 保持小，普通 Git；大量素材移可授權 CDN
完整原始碼 ZIP 供下載 GitHub Release
大型原始模型／設計素材版本收藏 獨立素材 repository 的 LFS，另計 storage/bandwidth
大量使用者串流大型景觀素材 合適的物件儲存＋CDN、分塊與懶載入
多 GB EXE／第三方安裝器 不納入本遊戲網站；引用合法原始來源

Release 是發放套件的功能，官方頁目前列每件小於 2 GiB、每個 Release 至多 1,000 附件，總量／流量沒有列同樣上限；這不等於任何流量模式都享有正式 SLA。網站執行時亦不要將整個 Release ZIP 當一個場景資產。[S4]

8.3 取消追蹤尚未需要的大檔

確認檔案只需留本地後：

git rm --cached PATH_TO_LARGE_FILE
git add .gitignore
git commit -m "Stop tracking large local archive"

這只讓下一個提交不再追蹤它，不會移除既有歷史中的大檔。若 100 MiB 大檔已進本地尚未推送的提交，請依 GitHub 官方的移除歷史教程處理，或建立乾淨的新分支／新 repository 後只搬必要檔案。不要未經確認改寫已分享的歷史。[S2]

8.4 上傳完整 ZIP 到 Release

先完成正常 commit／push，且 ZIP 放在專案外，例如上層目錄：

gh release create v3.0.0 ../AERO_Explorer_v3_FullPackage.zip --title "AERO Explorer v3" --notes "Complete source, assets and deployment guide"

版本 tag 與 ZIP 實際檔名按自己的檔案修改。已存在 Release 時可以透過 GitHub 網頁新增附件，或：

gh release upload v3.0.0 ../AERO_Explorer_v3_FullPackage.zip

同名附件已存在時先確認是否要替換，不要盲目使用覆蓋選項。Release 的原始碼自動 ZIP 與自訂完整套件 ZIP 可能不同，應清楚命名。

9. 容量推算：當前包體與 10 萬次冷啟動

9.1 本版本已量到的是磁碟原始大小

目前建置清單量到：核心 499,720 bytes、延後載入 3D 模組 490,547 bytes、水下礁石素材 291,846 bytes。以下按十進位 1 MB = 1,000,000 bytes、1 GB = 1,000,000,000 bytes 計算，不把 raw bytes 當已測過的網路傳輸量。

被載入專案 單次原始資料量 10 萬次首次下載資料量
核心 0.499720 MB 49.9720 GB
額外 3D 模組 0.490547 MB 49.0547 GB
核心＋3D 0.990267 MB 99.0267 GB
額外水下礁石 0.291846 MB 29.1846 GB
核心＋3D＋礁石 1.282113 MB 128.2113 GB

這是指定清單的自有檔案情境，不包括 Google 圖資、天氣 API 響應、其他未列專案、協定標頭、重試及未來加上的大型素材。輕量玩家不一定下載 3D，沒下水的玩家不一定下載礁石；反過來，網站的其他檔案仍有成本。

流量公式：

資料量 = 單次下載 bytes × 首次訪客數
平均外送 bit/s = 資料量 bytes × 8 ÷ 完成下載秒數

若 10 萬人都在 60 秒內取得核心＋3D＋礁石，以上原始量需要平均約 17.09 Gbit/s 的外送；若只拿核心約 6.66 Gbit/s。這不是單臺玩家的網速要求，也不是已做的 CDN 速度測試，而是整個服務輸出的推算。

Pages 的 100 GB/月軟性流量限制，與「每分鐘可以服務幾人」是不同指標。一次滿載冷啟動即使短時間沒有錯誤，也可能用掉整個或更多月流量。不能用「單次檔案不到 1 MB」推論「免費 Pages 保證 10 萬人」。[S1]

9.2 gzip／Brotli 和快取

伺服器應對 JS、CSS、HTML、JSON 提供 gzip 或 Brotli。WebP、JPEG、GLB 中已壓縮的 buffer/image 未必能再次大量壓縮。這份報告尚未完成正式發布站 Content-Encoding、transferSize 或真實 CDN 邊緣的測量，因此不報一個假裝精確的「壓縮後節省 80%」。

Chrome／Edge 開發者工具 → Network，使用 Disable cache 做冷啟動測量，然後關閉 Disable cache 做回訪測量。記錄 Content-Encoding、transferred、resource size、request count、首次可操作時間、長任務、FPS 與 JavaScript errors。測量時註明裝置、瀏覽器、網路、場景、語系及完整／均衡／輕量模式。

正式 CDN 設定範例策略：

檔案 建議策略 原因
有內容雜湊的 JS/CSS/GLB/WebP public, max-age=31536000, immutable 地址改版才更新，可長期快取
沒雜湊但放在 /releases/v3.0.0/ 的素材 同樣可長期快取 版本目錄不能覆蓋舊內容
index.html、語系入口 HTML 短快取或重新驗證 避免舊入口引用已刪的資產
Service Worker 程式 重新驗證／短快取 讓更新被偵測
自有 weather.json 按資料更新週期快取＋陳舊容忍 所有玩家共用，避免打上游
Google 圖資與第三方 API 依供應商規則與 response headers 不納入自有永久離線快取

GitHub Pages 的 response headers 不是由你在 repository 放一個任意 _headers 就能完整控制。若你需要自訂 edge cache policy、Origin shield、精確 bandwidth budget 或 admission 控制，請用支援這些功能的 CDN／主機。CDN 不會消除首次訪客下載，也不會替 Google 免費提供第三方內容。

10. 兩種發布架構與驗證方式

架構 A：GitHub Pages 靜態發布，玩家本機模擬

適合個人展示、教育試玩、逐步驗證。流程是 Git push → Actions build → Pages 靜態檔 → 玩家瀏覽器。遊戲不需要登入、資料庫或載具計算伺服器；地圖／天氣由使用者選擇，沒有設定時照常玩程式場景。

優點是部署簡單、程式碼易檢查、玩家互不分擔物理成本。容量上限是靜態供應商／外部 API 政策，免費 Pages 有大小、流量與限流規定。Pages 也不是通用商業 SaaS 免費主機；若網站變成收費軟體服務或商業交易平臺，須依其用途限制選合適主機。[S1]

不要把「同一網址每人本機運算」當成已驗證 CDN 吞吐。可以先從小規模真人裝置測試與站點流量統計開始，觀察訪問者的裝置檔位與錯誤，再決定升級。

架構 B：自訂網域＋物件儲存＋CDN，選用外部服務有獨立控制

適合準備大量公開流量。原始碼仍可放 GitHub；Actions 將不可變的版本檔案傳送至你有契約和費用預算的物件儲存，再由 CDN 提供。HTML 為短快取，帶版本／雜湊資產長快取，玩家物理依舊本機計算。

需要的具體配置包括：

  1. 確定預期冷啟動流量與尖峰視窗，向供應商確認 CDN 頻寬、request、object-size、費用、rate limit 與支援。
  2. 建置檔案分組，先下載核心，再按完整／均衡／輕量及水下需求載入。
  3. 原始素材放獨立版本路徑，儲存跨來源素材時設定正確 CORS；設 CSP 時只開放實際需要的來源。
  4. 天氣由你的同來源快取端點或定時靜態 JSON 供應；處理上游許可、每日配額、timeout、過期與回退。
  5. Google 實景按需載入，有額度限制、費用預算與錯誤回退；10 萬人不在第一頁自動 map-load。
  6. 監控 CDN 429／5xx、origin miss rate、首次可操作時間、JS 錯誤、低檔比例與地圖失敗。
  7. 新版本與舊資產一段時間並存，方便回滾，避免先刪舊素材再發布新 HTML。

這是可實作的正式部署方案說明；當前 ZIP 不會自動替你購買 CDN、申請提高 Google 額額或建立費用賬戶。是否達到 10 萬人，應以你的契約配置及授權負載測試報告為準。

10.1 容量測試與遊戲效能測試分開做

HTTP 負載測試看的是下載／API 服務，不會自動證明手機可穩定渲染。先在自己授權的 staging／CDN 測：10、100、1,000 等逐級提升，不直接對公共 Pages、Google、Open-Meteo 或別人的站點傳送 10 萬虛擬人。大量測試要與供應商確認，外部 API 用 stub 或受控 fixture。

測試應記錄冷快取／暖快取、總響應 bytes、p50/p95/p99 延遲、timeout、429/5xx、CDN 邊緣與 origin 流量。安全門檻可以設例如錯誤率、p95 下載與費用上限，超過就停止；門檻需按你的目標制定，不是本套件的已承諾 SLA。

渲染測試另用真實 Windows、Mac、Android、iOS 裝置，測試完整／均衡／輕量、長時間玩、切背景、裝置橫豎轉、觸控取消、WebGL context loss 與網路斷線。GPU 加速桌機的 30 秒測試不能代替低記憶體手機 15 分鐘測試。

10.2 素材增長時怎樣保持快

  • 紋理從適合手機的尺寸做起，按 LOD 選擇；不要一開場解碼數十張 8K 圖。
  • 重複樹、魚、礁石儘量例項化，共用幾何與材質，控制 draw calls。
  • 對遠景減少細節、動物數量和陰影；完整版本的更多細節不應改變基本操作。
  • 圖片優先 WebP 或經過相容驗證的 AVIF，GLB 按需用 Draco/Meshopt；解碼器也要隨套件/部署提供。
  • 大場景分塊並限制活動塊數；移走後釋放資源，不持有所有 object URLs 與紋理。
  • AI 生成圖片可作原創紋理，但不要將其標記為 Google 真實實景或某地方實測地形。

這些是擴充素材時的策略，未實現的素材技術不能宣傳為當前功能。

11. Google 實景：站主配置與玩家使用

11.1 建立站主自己的專案及 browser key

在 Google Maps Platform 建立自己的 Google Cloud 專案、適用帳單設定，啟用 Maps JavaScript API 與 Places API (New)，建立供瀏覽器使用的 APIkey。Demo key 只適合測試，不當作生產 key；官方地圖不是無限免費服務。[S5]

API key 設兩層限制：

  1. Application restrictions 選 Websites，只允許自己的 HTTPS 網域；測試可另外允許你實際使用的 localhost 來源。
  2. API restrictions 只允許本遊戲實際使用的 API，不設 unrestricted。

例：允許 https://YOUR_USERNAME.github.io/* 或正確 customdomain。瀏覽器通常會為跨來源請求只送 origin；若 loader 使用 auth_referrer_policy=origin，restriction 必須匹配 origin，不要只靠 /aero-explorer/ 路徑限制。不要開成 * 讓全網使用。[S6]

browser key 會出現在網頁網路請求中；把它放 owner 配置檔案而非聊天截圖是便於管理，不是保密手段。後臺 REST 服務需要另一把 API 受限／server-IP 受限 key，不能放 publicJavaScript，也不要把 backendsecret 混入 AERO_ORIGIN。[S6]

此版本站主配置位於 dist/config.js。完整範例如下：

globalThis.AERO_CONFIG = {
  googleMapsKey: '',
  weatherEndpoint: '',
  autoNearby: false,
  initialOrigin: {
    lat: 22.64954,
    lon: 120.35363,
    altitude: 20
  }
};

googleMapsKey 填入自己的受限制 browser key；若空白，選用 Google 功能先提示設定，本機場景仍可玩。這把前端 key 的保護來自 GoogleConsole 的 website/APIrestrictions，不是公開 JavaScript 的保密。initialOrigin.lon 的欄位是 lon，不是 Google 介面的 lng；遊戲 adapter 會轉換。

autoNearby:false 保持附近搜尋由玩家選擇觸發，避免一開頁就批次呼叫。若站主改成 true，應先評估 API 費用、quota 及流量，不能預設當免費自動推薦。altitude:20 是初始地圖海拔示例，玩家也可在介面 originAltitude 欄位修改；這不代表起點地面海拔已被實測。

試玩亦可在遊戲內實景設定填 key，僅記憶體儲存、不寫 localStorage。關閉／重新載入後，依介面重新填入；這項試玩設定不會自動提交到 GitHub。站主設定 dist/config.js 後，照常將這個來源檔提交並推送；每次建置後確認值有保留。不要以為 dist 只是可刪掉的輸出而丟失設定。

11.2 開啟實景與定位

遊戲先開啟本機場景，選擇 Google 實景後再載入地圖。定位需要 HTTPS 及瀏覽器許可；電腦定位可能來自網路/Wi-Fi，精度沒有手機 GPS 那麼確定。應看定位回傳的 accuracy 與時間，不能把地圖猜測的街區中心說成你實際所在門牌。

拒絕定位時，可自行選擇鳳山附近內建地點／輸入座標；這不會自動發現你當前位置。Google Nearby 在使用者操作後發一次搜尋，依實際回傳列附近景點、地址及 Google 連結；沒有 key／沒有結果時使用內建景點資料並標示來源。搜尋不是每一幀控制都會呼叫。

11.3 附近景點、語言與歷史

當前介面是 Place.searchNearby；JS 請求用 language、locationRestriction、includedTypes 和明確 fields。類別包括景點、博物館、公園、佛寺、醫院等，結果依範圍與 Google 資料，不保證每個指定地標必返回。GoogleNearby 提供名字／位置不代表提供歷史故事。[S7]

本套件內建 13 處的 22 語系簡短歷史/介紹是靜態編輯內容，不透過 Nearby 憑空生成。附近新地點若沒有內建介紹，應顯示名字、類別及 Google 詳情連結；不要當場編造歷史年份、開放時間、管制或真實海底生態。

請保留地圖內建 GoogleMaps 及第三方歸屬文字，HUD 與操縱桿不遮住。Google 內容的一般快取及離線下載有約束；ServiceWorker 只快取自有白名單，不打包 StreetView 圖片或 Google3DTiles。[S8]

11.4 相機與三用載具的真實邊界

3D 地圖裡的 cameraPosition 與 center 不同：前者是相機位置，後者是看向的點。最新版 Maps3D 的 center altitude 以平均海平面為基準；例如 altitude:20 表示海拔 20m 的請求，不等於在任意景點「離地 20m」，也不是地面測量。range 是相機與目標距離，不是傳統 zoom。[S9]

地圖實際可視高度／遮擋仍由官方渲染器與覆蓋資料決定。本地車輛高度、海面和地形是模擬座標，不應該直接視作真實建築內碰撞或水深。StreetView 在已拍全景處可看現實景觀，既非現場直播，也不是任意位置都能連續走進／飛進全景。

Google3D terrain 全球可用，立體建築／表面資料只覆蓋部分地區。指定鳳山街區有沒有完整 mesh，要查 coverage 或實際測試；不能用「是臺灣大城市」代替確認。[S10]

水下魚、珊瑚、湖底、鳥與雲是程式生成景物。它們可以有寫實外觀，但並非 Google 實時取回的當地生態。下水時應切到程式場景並清楚說明；真實海底需要另有授權攝影／360 影片／測繪資料。不能把澄清湖畫成珊瑚礁後稱當地實景。

本機 PNG 拍照匯出的是遊戲自身可匯出的模擬畫面。GoogleMap3D 或 StreetView 是獨立 renderer，不會因為本機 Three.js toDataURL() 就自動出現在 PNG 裡；依遊戲介面說明，檢視官方實景時可用裝置截圖，並保留地圖歸屬。

11.5 10 萬人與 Google 配額、費用

截至 2026-10-07 官方檔案，MapsJS 的 2D／3D map load 上限為每專案 30,000/min、每 IP300/min。10 萬人同一分鐘自動建地圖會超過預設 projectquota；程式碼變小不能避開。正式公開前從 GoogleConsole 評估額度、必要時申請調整，並設成本/額度監測。[S11]

Google3D JS 對應 ImmersiveMaps，按成功 mapload 計費。當前全球 pay-as-you-go 表列 5,000/月免費門檻，之後第一檔 USD7/1,000；100,000 次成功 3Dload、假設無其他用量或優惠，推算約 USD665 地圖費用，另有 Places、StreetView、稅金。這個數字是當前價表情境，不是最終賬單，也不是長期固定價格。[S12]

地圖載入後 pan/zoom 本身不計新 mapload，不應為了玩家每次控制重建 mapelement。重新建立、重新開頁仍可能觸發新 load。限制「每日預算提示」不等於硬性停止收費；應按 Google 提供的 quota 與告警功能配置，必要時關停選用地圖並繼續本機模式。

常見錯誤：

錯誤 優先檢查
MissingKey／InvalidKey owner 配置是否有有效 browserkey
RefererNotAllowed 實際 Pages／customdomain 是否被允許
BillingNotEnabled 專案帳單是否啟用且有效
ApiNotActivated MapsJS／PlacesAPI(New)是否啟用
OverQuota／429 usage／quota、流量尖峰、是否重複建立地圖

12. 天氣、硬體與維護

12.1 天氣使用原則

Open-Meteo 公開免費 API 僅非商業，限制少於 10,000/day、5,000/hour、600/min；其條款把廣告、訂閱及推廣網站列作商業使用。10 萬人每人開頁請求一次超出免費量，不能稱「永久免費大規模天氣」。按其 CCBY4.0 標示資料來源，商業或大量流量需適用方案／自架。[S13]

推薦預設手動天氣／明確標示的內建示例；正式更新由站主的授權上游與共享快取端點供應。網格去重、15–30 分鐘更新、CDN 共享、超時及陳舊回退可減少成本。儲存更新時間、來源、wind 單位，避免把 km/h 當 m/s；模型 10m 風不是每片雲或任意飛行高度的現場觀測。[S14]

本版 weatherEndpoint 指向站主自己的 HTTPS 快取端點，遊戲以 GET 附加 ?lat=...&lon=...；座標先四捨五入至小數 2 位，約為公里尺度，並非傳精確門牌。共享快取 worker 的設定與部署步驟見套件 backend/weather-worker/README.md。端點回傳相容的 Open-Meteo JSON：

{
  "current": {
    "time": "2026-10-07T13:00",
    "temperature_2m": 28.0,
    "wind_speed_10m": 2.0,
    "wind_direction_10m": 45,
    "cloud_cover": 30
  },
  "current_units": {
    "temperature_2m": "°C",
    "wind_speed_10m": "m/s",
    "wind_direction_10m": "°",
    "cloud_cover": "%"
  }
}

上述是 API 契約示例值，不是本次高雄天氣實測。上游請設定 wind_speed_unit=ms，使 wind_speed_10m 確實為 SI 的 m/s。端點可用附帶 worker 範例的 15 分鐘 TTL 與網格共享；跨來源端點要允許實際網站來源的 CORS。空端點表示不啟用網路天氣，本機模式可用。

遊戲顯示的天氣資訊與簡化載具物理應分清：當前模擬風仍為簡化模型，並未接入實時氣象作為真實飛行動力學。天氣不是飛行安全決策或該處每片雲的測量。不要將快取值寫成現場 live sensor。

不要將任意使用者 URL 變成開放代理。快取天氣不等於可以永久離線 Google 地圖，兩種資料各有許可。共享快取上線前另測真正的 upstream 請求量、超時與商業使用資格。當前沒有站主 Googlekey，所以 Maps 實景以 source 與 API 契約測試驗證；沒有實際收費專案、真實鳳山 mesh 或 10 萬連線實測結果。

12.2 自動硬體分級與手動覆蓋

瀏覽器 deviceMemory 只提供經隱私處理的粗略 RAM 提示，可能缺失；hardwareConcurrency 是可用邏輯 CPU 提示，不是處理器主頻。網頁不能準確知道「剩餘記憶體 64GB」或 GPU 剩餘 VRAM。不要以大量分配記憶體試到 crash 當檢測方法。[S15]

本版以提示、WebGL 可用性與實際小型渲染探測選完整／均衡／Canvas 輕量。自動值是建議；使用者可改模式。手機不一定都低效能，桌機也不一定都夠強，瀏覽器的軟體 renderer 或多工會影響結果。

相同裝置長時間發熱也會變慢，持續幀時間觀察與降檔比只讀 user-agent 更有意義。隱藏頁面暫停計算，重新出現限制 dt，失去焦點時清除按鍵，避免重新進遊戲載具突然衝刺。測試要看畫面操作，不把靜態頁面可以開啟當成完整遊戲測試透過。

12.3 釋出後的固定維護工作

每次更新保留版本 tag／Release、測量檔案大小、驗證 Pages 實際 URL 與子路徑、檢查選用 Map 錯誤、抽測 22 語系與阿拉伯 RTL。Google／天氣 API、價格、瀏覽器支援會改變，官方介面升級後先在 staging 測試。

若出現大量錯誤，先回滾至已驗證版本，保留對應資產；使用者仍可進入輕量模式。檢查監控的 429／5xx／JSerror／WebGLlost，而不是先責怪玩家裝置或建議清除整個電腦。

13. 常見問題速查

Q：我把 ZIP 上傳 GitHub，為什麼 Pages 不會跑？

A：ZIP 是附件，Pages 需要展開的 HTML 與資源。提交原始碼後讓 Actions 構建dist，或直接釋出完整dist內容。

Q：需要每個玩家 npm install 嗎？

A：不用。站主／CI 建置，玩家只在瀏覽器開啟已釋出檔案。

Q：GitHub Pages 可以執行 Python 天氣伺服器嗎？

A：不行，Pages 只供靜態內容。天氣共享服務須另外部署，或定時產生靜態 weatherJSON。[S16]

Q：git push 被 reject 怎麼辦？

A：先git status，取得遠端變更並解決衝突。確認 remote／branch 與是否有 100MiB 大檔。不要預設 forcepush。

Q：npm ci 報 lock 不一致？

A：原始碼和 lock 必須來自同一套件。若你有意改 dependency，開發機正常更新 lock 並測試後 commit；CI 不應臨時自行改版本。

Q：Photos／Google 實景都可以完全離線嗎？

A：自有遊戲資源可按白名單離線；Google 圖資仍需網路與許可權，沒有任意離線下載授權。

Q：10 萬人獨立玩和真正多人房間哪一種已經有？

A：當前是獨立瀏覽器模擬。正式靜態吞吐需部署測試；多人房間同步尚未實現。

Q：為什麼手機沒有完整實景？

A：可能自動分級、WebGL／硬體加速、API key、網路或該地覆蓋。輕量可用不意味著必能跑 Google3D。

Q：能保證無 delay 嗎？

A：操作與物理不等待外部伺服器，減少網路影響；渲染仍受裝置與負載，地圖串流仍受網路。不能保證所有裝置零延遲。
